# AgentsVille AI Trip Planner

A Jupyter Notebook-based AI travel planning application that uses LLMs with the
**ReAct (Reasoning + Acting)** framework to generate, evaluate, and iteratively
refine personalised travel itineraries.

## Project Overview

The AgentsVille AI Trip Planner generates day-by-day travel itineraries tailored
to a traveller's interests, budget, and constraints.  It then **automatically
validates** the itinerary against five quality checks and, if any check fails,
dispatches a revision agent that reasons about the problems and fixes them
autonomously—no human intervention required.

### Key Features

| Feature | Description |
|---|---|
| Pydantic data models | Structured, validated input and output |
| Simulated activity catalog | 18 weather-aware activities across 7 categories |
| 5-check evaluation system | Rule-based + LLM-based quality gates |
| ReAct revision loop | Agent reasons and acts until all checks pass |
| Narrative trip summary | Friendly prose summary generated by the LLM |
| Test scenarios notebook | 6 diverse traveller profiles validated end-to-end |

```
└─────────────────┬───────────────────────────────────────────┘
                  │
                  ▼

│                   ItineraryAgent                            │
│          (LLM call with JSON response mode)                 │
│              -> produces TravelPlan                         │
└─────────────────┬───────────────────────────────────────────┘
                  │
                  ▼
┌─────────────────────────────────────────────────────────────┐
│                   run_evals() - 5 checks                    │
│  budget_accuracy | city_date_correctness | min_activities   │
│  activity_availability | weather_compatibility (LLM)        │
└──────┬──────────────────────────────────┬───────────────────┘
       │ all pass                         │ any fail
       ▼                                  ▼
┌────────────────┐            ┌───────────────────────────────┐

│    summary()   │            │   ReAct loop (max 10 itr.)    │

└────────────────┘            └───────────┬───────────────────┘
                                          │ final_answer_tool
                                          ▼
                              ┌───────────────────────────────┐
                              │   Final validated TravelPlan  │
                              └───────────────────────────────┘
```

## Usage Examples

### Minimal Example

```python
from openai import OpenAI
from project_lib import (
    VacationInfo, get_weather_forecast, get_available_activities,
    ItineraryAgent, run_evals, print_itinerary,
)

client = OpenAI()

vacation_info = VacationInfo(
    destination="AgentsVille",
    start_date="2025-06-15",
    end_date="2025-06-17",
    interests=["culture", "food"],
    budget=300.0,
)

weather_data = get_weather_forecast(vacation_info)
available_activities = get_available_activities(vacation_info, weather_data)

agent = ItineraryAgent(client, model="gpt-4o")
plan = agent.generate(vacation_info, weather_data, available_activities)

eval_results = run_evals(
    plan, vacation_info, weather_data, available_activities, client
)
print_itinerary(plan)
```

### With Revision and Summary

```python
from project_lib import ItineraryRevisionAgent, generate_trip_summary

revision_agent = ItineraryRevisionAgent(client, model="gpt-4o")
if not eval_results["all_passed"]:
    plan = revision_agent.revise(
        plan, vacation_info, weather_data, available_activities
    )

plan.summary = generate_trip_summary(plan, vacation_info, client)
print_itinerary(plan)
```

### Custom VacationInfo Parameters

```python
VacationInfo(
    destination="AgentsVille",
    start_date="2025-07-01",
    end_date="2025-07-05",
    interests=["outdoor", "sports"],   # drives activity selection
    budget=800.0,
    constraints=["vegetarian", "no-alcohol"],   # optional
)
```

## How the ReAct Loop Works

The `ItineraryRevisionAgent` implements the **ReAct (Reasoning + Acting)**
pattern, alternating between reasoning steps and tool calls:

```
Step 1 - THOUGHT
  The agent reads the current itinerary and evaluation failures.
  It reasons: "Day 2025-06-15 has Beach Volleyball scheduled but the
  weather is rainy - I need to replace it with an indoor activity."

Step 2 - ACTION (tool call)
  get_activities_by_date_tool("2025-06-15")
  -> returns all available activities for that date filtered by weather.

Step 3 - OBSERVATION
  The tool returns: {"weather": "rainy", "available_activities": [...]}

Step 4 - THOUGHT
  "I'll replace Beach Volleyball ($15) with City Museum Tour ($30).
  I must recalculate day_total_cost and total_cost."

Step 5 - ACTION
  calculator_tool([30.0, 45.0])   <- verify arithmetic

Step 6 - ACTION
  run_evals_tool({...revised plan...})   <- run all 5 checks

Step 7 - OBSERVATION
  {"all_passed": true, ...}

Step 8 - ACTION
  final_answer_tool({...final plan...})   <- submit
```

The loop repeats for up to `max_iterations` (default: 10).

## Evaluation System

Five automated checks must all pass before a plan is accepted:

| Check | Type | What It Verifies |
|---|---|---|
| `budget_accuracy` | Rule-based | `day_total_cost` sums match activities; `total_cost` <= budget |
| `city_date_correctness` | Rule-based | Destination matches; all trip dates present, no extras |
| `minimum_activities` | Rule-based | Every day has >= 2 activities |
| `activity_availability` | Rule-based | Every activity is in the catalog for that date's weather |
| `weather_compatibility` | LLM-based | Activities are appropriate for the day's weather |

The LLM-based weather check uses `gpt-4o-mini` with a JSON response format for
reliable structured output.

## Troubleshooting

| Symptom | Likely Cause | Fix |
|---|---|---|
| `AuthenticationError` | Missing or invalid API key | Set `OPENAI_API_KEY` env var |
| `RateLimitError` | Quota exceeded | Wait, or upgrade your OpenAI plan |
| Budget check fails repeatedly | LLM arithmetic errors | The revision agent will auto-fix; increase `max_iterations` if needed |
| Notebook kernel dies | Out of memory | Reduce trip length or restart kernel |
| `pydantic.ValidationError` | LLM returned malformed JSON | Re-run the cell; the LLM response is non-deterministic |

See [TROUBLESHOOTING.md](TROUBLESHOOTING.md) for a full FAQ.
